# Passport PR #5：聆听恢复与字形内存修复

## 真机发现

2026-10-11，PR #5 的 `339b095` 应用固件在短按自动聆听模式下：

1. 第一轮正常回答，回到聆听后 MQTT 收到 TCP FIN；应用没有退出聆听。
2. 一次性重连定时器只在 idle 执行，忙状态会跳过重连；旧音频通道持续超时。
3. 短按退出再进入可以收到回答，但随后出现 `TextGlyphAllocator failed to allocate glyph storage` 并崩溃重启。

日志保存在主检出目录的私有 `backups/ai-passport/2026-10-11/listening-diagnosis/`，不提交设备备份和原始对话日志。连接被关闭的网络原因仍未确认。

## 修复边界

- MQTT 断线回调只在应用主任务清理旧 UDP 会话、报告连接错误并安排重连。
- 忙状态或连接失败保留后续重连尝试；客户端代次和存活标志防止旧回调清理新会话。
- 活跃聆听/说话期间检查通道有效性；120 秒接收超时走应用错误清理，不再永久停留在聆听。
- 不改变 NVS、网络凭据、按键语义或默认唤醒词设置。
- 字形位图在协议、字幕保留缓存、显示缓存间共享，不重复复制位图。写入只发生在解析阶段；交给缓存后按只读对象处理。
- 无 PSRAM 的解析与显示缓存位图预算都是 8 KiB；PSRAM 设备保留原 64 KiB 预算。
- 字形位图与动态字体输出数组使用精确大小、可失败的分配。失败时跳过本批动态字形或清空动态字体，继续显示基础字体可覆盖的字符；部分字符可能缺失，但该失败路径不再主动 abort。
- 这是字形存储的分配降级，不代表已解决系统所有标准容器/cJSON/LVGL 的极端低内存分配风险。
- GitHub Actions 附带匹配该固件的 ELF/map，供下一次现场栈解析。

## 回归验证

主机测试执行实际生产生命周期回调和字体缓存代码，覆盖：

- 网络回调到主任务调度、失效 UDP 关闭、忙状态重试、失效代次/已销毁对象的排队回调。
- 活跃会话超时进入错误清理；健康通道、空闲和通知播放不受该超时检查影响。
- 位图分配失败不退出进程；缓存复制不增加位图分配；失败的 resize 保留原对象。
- 字体构建的四处存储分配分别失败后降级、恢复，以及多个 Unicode 范围的输出指针有效性。
- 既有字幕 UTF-8 保留/分页、PTT 和超预算批次不绕过 Passport 缓存限制。
